# 验收用例一行纸

> 每次功能交接时，策划方出这个表，开发方通过才算交棒。

---

## 用例 1：诊断 → 告警

| 字段 | 内容 |
|------|------|
| **输入** | `GET /api/bases/:id/diagnostics` 返回的 `issues` 数组 |
| **期望输出** | alerts.md 新增行包含 issue 的实际描述文字（非 `?`） |
| **验收方式** | 跑一次 Bridge 调度，读 alerts.md 最后一行，人工确认内容有信息量 |
| **失败判定** | 告警内容含 `?` 或无 issues 时仍写入告警 |

## 用例 2：订单 Link 完整性

| 字段 | 内容 |
|------|------|
| **输入** | 销售订单表所有记录 |
| **期望输出** | 每条订单的客户 link + 产品 link 均非空 |
| **验收方式** | `SELECT COUNT(*) FROM links WHERE field_id IN (客户字段ID, 产品字段ID)` = 订单数 × 2 |
| **失败判定** | links 表计数 < 订单数 × 2 |

## 用例 3：结算异常触发

| 字段 | 内容 |
|------|------|
| **输入** | 结算表中结算状态 = "待结算" 的记录 |
| **期望输出** | 诊断 issues 中包含 `completed_unsettled_orders` 或类似异常码 |
| **验收方式** | 调用诊断 API，检查返回 issues 中是否有待结算相关条目 |
| **失败判定** | 存在待结算记录但诊断 issues 为空 |

## 用例 4：Dashboard 不崩溃

| 字段 | 内容 |
|------|------|
| **输入** | 空 base 或刚初始化模板的 base |
| **期望输出** | `GET /api/bases/:id/dashboard/summary` 返回 200，无 500 |
| **验收方式** | 对空 base 调 dashboard API，确认 HTTP 200 |
| **失败判定** | 返回 500 或 `Cannot read properties of null` |

## 用例 5：密码策略拦截

| 字段 | 内容 |
|------|------|
| **输入** | 注册请求，密码 = `pass123456`（弱密码） |
| **期望输出** | 返回 400，提示密码强度不足 |
| **验收方式** | 调用 `POST /api/register`，确认返回 400 |
| **失败判定** | 弱密码注册成功 |

## 用例 6：诊断字段映射

| 字段 | 内容 |
|------|------|
| **输入** | 诊断 API 返回的 issue 对象 |
| **期望输出** | issue 包含 `message` 和 `type` 字段，且值非空 |
| **验收方式** | 打印诊断返回 JSON，检查每个 issue 的 `message` 和 `type` |
| **失败判定** | `message` 为 undefined 或 `type` 为 undefined |
