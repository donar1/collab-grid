# CollabGrid 三层架构边界

## 第一层：操作界面 / 通用表格能力

这一层只解决“用户如何操作表格”，不承载业务含义。

核心能力：
- 空间、成员、角色、权限
- 表、字段、记录、单元格
- 关联字段、lookup、快照字段
- 按钮 action、封账/解封
- 批量写入、实时同步、审计日志

代码入口：
- `server.js` 现有通用路由
- `layers/tableLayer.js` 表格能力边界定义
- 后续可继续拆成 `routes/tables.js`、`routes/records.js`、`routes/cells.js`、`routes/links.js`、`routes/buttons.js`

## 第二层：核心业务关系

这一层只定义五个核心业务对象：产品、客户、订单、账单、库存。

### 五个核心对象

| 对象 | 主要表 | 负责字段/职责 | 被谁调用 |
|---|---|---|---|
| 产品 | `产品名称数据源区`、`产品信息区` | 售价、成本、货号、产品快照 | 订单、库存 |
| 客户 | `资源档案中心`、`财务结算对象区` | 企业名称、合作渠道、结算对象 | 订单、账单、业务锁定 |
| 订单 | `订单管理区`、`退款处理区`、`撤单处理区` | 产品、付款方、收款方、订单状态、应收/应付 | 库存、账单、佣金作业、大屏 |
| 账单 | `应收结算明细区`、`应付结算明细区`、`收付款流水区`、`财务红冲处理区` | 应收、应付、红冲金额、明细状态 | 财务核算、大屏 |
| 库存 | `库存商品区`、`出入库操作区`、`库存流水区` | 实际库存、虚拟库存、仓储、成本 | 大屏 |

### 调用链路

1. 产品 -> 订单：订单选择产品，并沉淀售价、成本、产品名称快照。
2. 客户 -> 订单：订单通过付款方/收款方关联客户或渠道资源。
3. 订单 -> 账单：完结订单生成应收/应付结算明细；撤单/退款只标记是否需要红冲。
4. 订单 -> 库存：付款方为自营时出库扣减实际库存；非自营不扣库存。
5. 库存 -> 产品：入库审核后更新库存成本，并同步产品成本。
6. 账单 -> 财务核算：账单明细作为核算输入；封账后只能通过红冲形成反向明细。

代码入口：
- `layers/businessRelations.js` 五个对象与调用链路定义
- `/api/system/business-relations` 可读取当前架构关系

## 第三层：附加价值层

第三层包含数据大屏和财务核算优化。

原则：
- 只读取第一层和第二层已经确认的结果。
- 不反向写核心业务数据。
- 可以后续慢慢优化，不阻塞核心业务系统稳定。

当前模块：
- `GET /api/bases/:baseId/dashboard/summary`
- 财务对账明细生成、红冲、封账
- 诊断中心和作业运行历史

## 当前拆分状态

本次先完成边界拆分和 P0 风险解除，没有一次性大搬迁路由，避免引入大范围回归风险。后续建议按以下顺序渐进迁移：

1. `server.js` 中的字段/记录/单元格路由迁移到 `routes/grid/*`。
