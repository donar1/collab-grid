# CollabGrid V0.3 版本说明

发布日期：2026-06-21

## 版本定位

V0.3 是一次结构治理版本，目标不是继续堆业务功能，而是先把系统主干按三层结构稳定下来：

1. 第一层：操作界面 / 通用表格能力
2. 第二层：产品、客户、订单、账单、库存五个核心业务对象
3. 第三层：数据大屏和财务核算附加价值层

## 本次完成

### 版本标识

- `package.json` 已升级到 `0.3.0`
- `package-lock.json` 已同步到 `0.3.0`

### 表格通用路由拆分

从 `server.js` 迁移到 `routes/grid/`：

| 模块 | 文件 | 职责 |
|---|---|---|
| 表格/字段 | `routes/grid/tables.js` | 表分页、搜索、建表、字段增删改锁定 |
| 记录 | `routes/grid/records.js` | 记录新增、更新、删除、封账基础状态 |
| 单元格 | `routes/grid/cells.js` | 单元格写入、样式写入、只读字段保护 |
| 关联 | `routes/grid/links.js` | link 字段增删、lookup 快照重算、订单产品默认值同步 |
| 按钮 | `routes/grid/buttons.js` | 按钮 action 分发、审批、封账、红冲、库存审批 |
| 批量 | `routes/grid/batch.js` | 批量 `cell.update` 操作 |

### server.js 变化

- `server.js` 保留启动、鉴权、中间件、核心 helper、业务模板、作业、大屏和成员邀请等入口。
- 表格通用能力通过 `gridRouteContext` 注入到 `routes/grid/*`。
- 前端 API 路径保持不变，无需改前端调用。

### 安全基线延续

- 生产环境强制 `JWT_SECRET`
- 生产环境强制 `ALLOWED_ORIGINS`
- 登录/注册限流
- query token 已禁用
- 按钮审批路径继续遵守封账守门

## 下一步建议

V0.3 后半段已继续拆第二层核心业务：

1. `routes/core/products.js`
2. `routes/core/customers.js`
3. `routes/core/orders.js`
4. `routes/core/bills.js`
5. `routes/core/inventory.js`

数据大屏和财务核算继续作为第三层附加模块，不反向写核心业务数据。

## 第二层核心业务拆分

本次新增：

| 模块 | 文件 | 职责 |
|---|---|---|
| 产品 | `routes/core/products.js` | 产品名称数据源区、产品信息区初始化 |
| 客户 | `routes/core/customers.js` | 资源档案中心、员工档案、业务锁定区、状态变更日志初始化 |
| 订单 | `routes/core/orders.js` | 订单管理区初始化、批量订单导入 |
| 账单 | `routes/core/bills.js` | 财务结算对象、应收/应付明细、收付款流水、红冲/退款/撤单处理区初始化，以及账单明细生成入口 |
| 库存 | `routes/core/inventory.js` | 库存商品区、出入库操作区、库存流水区初始化 |

拆分后，`server.js` 通过 `coreRouteContext` 挂载第二层核心业务路由，原 API 路径保持不变。
