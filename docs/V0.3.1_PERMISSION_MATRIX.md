# V0.3.1 — 权限矩阵与内外库分离

## 改动一览

### 1. 角色体系：两层 + 一个外部

| 层 | 角色 | 中文 | 说明 |
|---|---|---|---|
| 系统级（`users.system_role`） | `sys_admin` | 系统管理员 | 全权 + 可改任何角色的权限矩阵 |
| 系统级 | `data_engineer` | 数据员（全局） | 可改底层数据/结构、跑维护任务、看诊断 |
| 系统级 | `none` | 普通用户 | 默认值 |
| Base 级（`members.role`） | `manager` | 管理（含财务） | 业务/财务最高权限，可邀请改成员、封账、跑任务 |
| Base 级 | `business` | 业务 | 读写记录、审批业务锁定/订单，不改结构 |
| Base 级 | `data_clerk` | 数据员 | 数据修复：可改结构/记录、跑任务，但不审批/封账 |
| Base 级 | `support` | 客服 | 只读 + 大屏 + 审计 + 客户查询 |
| Base 级 | `warehouse` | 库管 | 读写记录 + 库存出入库审批 |
| 外部 | `customer_query` | 客户查询 | 仅限外部库，只查自己的快照 |

第一位注册用户**自动**成为 `sys_admin`，确保系统总有一个可改矩阵的人。

V0.3.1 补充：系统启动时如果没有任何 `sys_admin`，会自动创建一个默认系统管理员：

```
账号：admin@collabgrid.local
密码：Admin@123456
```

也可以通过环境变量覆盖：

```
DEFAULT_ADMIN_EMAIL=admin@example.com
DEFAULT_ADMIN_PASSWORD=自定义强密码
DEFAULT_ADMIN_DISPLAY_NAME=系统管理员
```

默认管理员会标记 `mustChangePassword=1`，登录响应会返回
`user.mustChangePassword=true`。用户可调用：

```
POST /api/auth/change-password
{
  "currentPassword": "旧密码",
  "newPassword": "新密码，至少 8 位"
}
```

修改成功后，旧密码立即失效，`mustChangePassword` 清零，并记录审计日志
`auth.password.change`。

旧角色（owner / admin / approver / finance / editor / viewer）仍可存入 `members.role`，
权限计算时通过 `security/roles.js` 的 `LEGACY_BASE_ROLE_MAP` 映射到新角色，所有旧测试零修改。

### 2. 权限码（23 项）

`security/permissions.js` 集中维护。覆盖结构/记录/封账/各类审批/任务/成员/审计/大屏/诊断/
矩阵自身写权/底层库维护/外部客户查询。

`server.js` 中原本散落的 `canManageStructure / canEditData / canSealRecord /
canApprove / canRunJobs / canManageBase` 全部代理到新的 `security.can*`，背后走
权限码查询，**业务路由零修改**即可受益于矩阵变更。

### 3. 矩阵存储 + 合并

`security/matrixStore.js` 新建 `permission_overrides(scope, role, base_id, permission, allow)`，
合并顺序：默认矩阵 → 系统级覆盖 → 外部覆盖 → base 级覆盖；显式拒绝（`allow=0`）优先。

### 4. 新 HTTP 入口

```
GET    /api/security/permissions            权限码 / 角色字典（任何登录用户）
GET    /api/security/me                     当前用户在每个 base 的有效权限
GET    /api/security/matrix                 全局矩阵（sys_admin / data_engineer 可见）
GET    /api/bases/:baseId/security/matrix   单 base 矩阵 + 我自己的权限
PUT    /api/security/matrix                 sys_admin 批量改写
PUT    /api/bases/:baseId/security/matrix   sys_admin / 有 matrix.write 的 manager
PATCH  /api/security/users/:userId/system-role  sys_admin 提权 / 降级用户

POST   /api/bases/:baseId/public/clients              颁发客户查询 token
GET    /api/bases/:baseId/public/clients              列出该 base 的客户 token
DELETE /api/bases/:baseId/public/clients/:token       撤销
POST   /api/bases/:baseId/public/snapshots/sync       手动同步快照到外部库

GET    /api/public/me                       外部库：使用 X-Customer-Token
GET    /api/public/snapshots                外部库：只查自己的 snapshots
```

### 5. 内外库分离

| 库 | 文件 | 内容 |
|---|---|---|
| 内部库 | `data/collab-grid.db` | 所有业务表（users / bases / members / tables / fields / records / cells / links / invites / audit_log / job_* / commission_* / order_activity_daily / **permission_overrides**） |
| 外部库 | `data/collab-grid-public.db` | `public_clients`（外部 token）、`public_customer_snapshot`（推送给客户的可见快照）、`public_access_log`（外部访问审计） |

外部 API 走独立 `publicDb`，**不持有内部 db 句柄**；快照通过显式的同步函数从内部推送出去，
内部业务字段永远不通过外部 API 暴露。外部 token 使用 `X-Customer-Token` 头，内部 JWT
无法通过外部接口验证。

### 6. 测试

新增 `tests/permission_matrix_test.js`：
- 第一位用户自动 sys_admin
- 5 个新角色的默认权限符合矩阵
- 矩阵改写后业务路由立即生效（support 获得/失去 `record.write`）
- 非 sys_admin 不能改全局矩阵
- 客户 token 仅能取自己快照、撤销立即失效
- 外部接口拒绝内部 JWT、内部接口拒绝外部 token

回归：12 个已有测试套件 + 权限矩阵 + p0-security 全绿。

```
npm run check                # 语法
npm run test:permission      # 权限矩阵
npm run test:p0              # 基础回归
npm run test:team-scale      # 团队权限（兼容 viewer/approver 等旧角色）
npm run test:order/inventory/finance/dashboard/...
```
